# 真实 UGC × AIGC：第二轮案例驱动研究

2026-09-29 · 单张 RTX 3090 / 24GB · 本地 ComfyUI · 目标：真实拍摄观感的混合视频

**这一轮建议把重点收敛到：保留真人换环境、保留真商品换场景、真人口播局部改写，以及短片段的局部修补。** 新增的商业案例支持这种分工方式，但没有证明一张 3090 能直接复刻整部广告，也没有证明任意 UGC 都适合自动处理。

本轮包含 **11 个案例／公开演示样本、6 个新增工作流参考文件、5 组对照实验设计**。结合上一轮，共保存 24 个参考 JSON；其中本轮 4 个是 UI 图、2 个是 API 图。文件下载和结构检查已完成，GPU 运行与效果验收未完成。语音示例文件的默认文案与音频路径已替换为中性占位，修改记录见附件。

阅读入口：[案例观看清单](案例观看清单.md) · [新增工作流与核查结果](新增工作流与核查结果.md) · [实验任务单](实验任务单.md) · [第一轮完整分类](../调研报告.md)

## 1. 这一轮改变了哪些判断

| 第一轮的路线 | 新案例带来的修正 | 对当前工作台的影响 |
| --- | --- | --- |
| 商品与局部物体编辑 | 必须拆成“保留真商品、改变周边”和“重生成商品本体”；后者对小字、形状、手部接触要求更高 | 优先做商品保护遮罩，把包装和握持的手一起保留下来 |
| 人物替换是一条主线 | 真人保留、环境生成同样能构成完整产品，且更容易定义必须保真的区域 | 新增“保护区域”和“编辑区域”，不能只记录替换人物 |
| 一条工作流生成一个结果 | 商业案例存在多次局部修补和跨工具合成 | 保存版本、时间段、局部区域和回贴参数，允许只重跑失败部分 |
| 补光属于后期增强 | 前景背景不匹配时是关键能力，但生成式补光也可能改变脸和商品 | 普通调色与 UniLumos 必须做对照，不能默认后者更好 |
| 首尾帧／转场都归时间编辑 | Clip Joiner 改写接缝，FLF 生成中间段，两者输入与保真目标不同 | 两段视频、首尾图片应是不同的模板和输入槽位 |
| 有公开 JSON 就接近可运行 | 存在旧节点名、子图、双视频输入、默认回放模式与文档误链 | 导入前先做输入和版本审查；UI 图与 API 图分别处理 |

这里的排序是针对你的需求和硬件做的工程判断，不是公开模型榜单排名。

## 2. 案例证据怎么读

“真实案例”在本报告中分为三类，分别回答不同的问题：

- **实际发布项目**：证明有人把该方法用于交付，但通常拿不到完整图和失败样本。
- **创作者制作实验**：有操作过程或文件，适合学流程；可能经过挑选，也可能使用 AI 原始片。
- **作者研究演示**：输入与输出容易比较，适合设立实验；不能当作真实业务通过率。

本轮核验了作者页面、制作说明、公开仓库和工作流结构。**没有完成所有视频的逐帧播放审阅，因此不提供虚构的时间码、观感评分或“某一帧完美”的结论。** 下面的案例事实来自所引来源；“本地迁移”和“建议实验”是本报告设计，不冒充案例原厂方案。需要人工看片核对的问题已集中列在观看清单。

## 3. 11 个案例与可迁移的方法

### C01 · Salomon「Shaping New Futures」：真人实拍进入 AI 世界

**证据：实际发布项目。** BBDO 的 2026 年项目页明确说明真人实拍与 AI 影像混合；UNVEIL 的作品页提供 45 秒影片及制作名单。制作访谈进一步说明采用绿幕真人拍摄、预演和 AI 环境处理。它是一部经过设计的品牌影片，风格包含超现实环境，不能直接等同于日常 UGC。[BBDO 项目](https://bbdo.fr/project/shaping-new-futures/) · [UNVEIL 成片](https://unveil.fr/salomon-shaping-new-futures) · [制作访谈](https://runway.com/customers/inside-salomons-latest-global-brand-campaign-built-on-runway)

**可以借鉴的分工：** 真实演员负责表演和身份，AI 负责环境变化。前期拍摄就考虑最终背景、机位与光向，而不是拿到任何素材后才尝试替换。

**本地迁移：** 固定机位真人视频 → 分割／抠像 → 生成与原机位匹配的静态背景或轻运动背景 → 保留真人像素合成 → 调色与边缘处理。光照差异过大时再测试 C07 的补光。ComfyUI 起点为第一轮 W02；背景动画可用 W06 的 Wan 5B I2V。完整合成链尚需搭建。

**适合你的成片：** 同一个人讲同一句话，分别处于家庭书房、咖啡馆、展厅。先选腰部以上、无大幅走动的 2–3 秒镜头，场景保持日常写实。避免第一轮就挑战人物跨越复杂地面和大幅运镜。

**不能据此推断：** 商业片使用 Runway 等制作工具；本报告给的是本地替代路径，没有等价质量或成本证明。

### C02 · Visa × Intesa Sanpaolo 冬奥广告：AI 是反复修补的一环

**证据：实际项目获制作公司确认；具体 AI 工艺来自参与者自述。** BRW 公布该广告采用 AI 与 live action，AI 团队为 Dogma。自称 Dogma 成员 Paolo 的发布帖描述了演员素材、LoRA、I2V、VACE 修补和剪辑交接，并明确说主要使用云端 H100，经历大量测试。两份来源分别支持“项目存在”和“工艺自述”，证据强度不混用。[BRW 制作说明](https://it.linkedin.com/posts/brw-filmland-s.r.l._la-stagione-degli-sport-invernali-%C3%A8-gi%C3%A0-activity-7377289912024436736-fJph) · [参与者帖子及回复](https://www.reddit.com/r/comfyui/comments/1nqcxg3/new_work_is_out/)

**可以借鉴的分工：** 一个总体可用的镜头，可能只需要修一处服装、背景结构或人物局部。把失败归到具体区域和时间段，比分不清原因地重抽整段更有操作性。

**本地迁移：** 使用已有人物替换输出作为母版 → 选 1–2 秒失败区间 → 生成稳定遮罩 → 裁出带上下文的局部 → VACE 编辑 → 用同一个变换与软边遮罩回贴。首轮不训练角色 LoRA；先证明局部返修能提升通过率。

**适合你的成片：** 真人测评中去掉背景杂物、修复 AI 换装的一小片闪烁、替换背景海报等。含手指、产品接触的复杂修补后置。

**不能据此推断：** 未公开项目完整 JSON、训练数据和单镜头成本。其 H100 制作经历尤其不能拿来作为 3090 速度或成功率依据。

### C03 · Tool「Cruise Control」：产品保真与环境变化分开

**证据：商业制作团队的管线展示／试点自述。** Runway 的团队访谈介绍了基于真实驾驶素材、跟踪替换和定制 LoRA 的汽车内容流程，并列举汽车品牌试点。产品严格保真与效率提升均属团队宣传性陈述；没有公开足以独立验证这些指标的完整工作流。[Tool 制作团队访谈](https://runway.com/customers/how-runway-powered-tools-cruise-control-pipeline)

**可以借鉴的分工：** 商品本体是受保护资产，环境是变化空间。对于你的工作台，比“把 A 商品生成成 B 商品”更值得先做的是“同一件真实商品在不同真实感场景中展示”。

**本地迁移：** 桌面真商品＋手部实拍 → 将商品、握持手、必要接触面组成保护层 → AI 生成周围场景 → 按遮挡顺序合成。后续再单独处理投影和接触阴影；不以生成修复包装小字作为默认方案。

**适合你的成片：** 同一杯饮料在书桌、露台、厨房中展示；同一包装产品的场景化短视频。先用不透明哑光物体，透明瓶、镜面金属和大幅移动后置。

**边界：** 保留像素能保护文字，但不会自动修正反射、透视或阴影。汽车案例复杂度很高，本地首测应缩小到桌面固定机位。没有公开的“Cruise Control ComfyUI 同款图”。

### C04 · Computerphile「MikeBot」：真实身份素材驱动的新视频

**证据：创作者项目＋公开文件。** 作者描述由脚本、人物图像生成、I2V、F5-TTS、LatentSync 组成的链路，也说明展示结果经过挑选，完整编排代码尚未发布。它更多是用真实身份／声音资料生成新视频，不能算保留整段原始 UGC 像素的例子。[作者仓库](https://github.com/Lewis-Stuart-11/MikeBot)

**本轮拿到的文件：** F5-TTS 与口型两个 API 图。静态核验发现口型图使用 `D_LatentSyncNode`、`D_VideoLengthAdjuster`，而当前常用 wrapper 注册名称为无 `D_` 前缀版本；旧图不能直接视为当前可执行模板。[当前节点映射](https://raw.githubusercontent.com/ShmuelRonen/ComfyUI-LatentSyncWrapper/main/nodes.py)

**本地迁移：** 先拿自己的实拍口播和真人录音跑口型，保持脚本、声音、画面来源可控。稳定后才决定是否增加 TTS 与人物图像生成。这样可以隔离“口型失败”和“合成声音不自然”两种问题。

**额外核查：** 文件名包含 frame interpolation，但这份 API 图并没有独立 FILM／RIFE 节点；长度调节默认是 `pingpong`。对倒水、走路等不可逆动作，这种往返补时不合适。使用等长输入或先剪好时长，再接当前版本节点。

**定位：** 作为“真实身份参考＋生成表演”的旁支保留，优先级低于直接编辑真实口播。人物模型与语音权重并未随项目完整提供。

### C05 · LatentSync 官方实拍口型对照：最直接的真实视频局部改写

**证据：研究作者的成对演示。** 仓库 Demo 给出 Original video 与 Lip-synced video，包含 `demo2` 至 `demo5` 的 v1.6 对照；作者说明写实视频由签约模特拍摄。官方列出的 v1.6 最低推理显存为 18GB，这只说明值得在 24GB 上验证，不是整条 Comfy 图一定能跑的保证。[官方 Demo 与配置说明](https://github.com/bytedance/LatentSync)

**本地迁移：** 用第一轮已保存的 LatentSync wrapper UI 图起步，核对 checkpoint 与当前插件版本；不从 MikeBot 旧 API 图盲改节点名。准备 25fps、单人正面、光线稳定、音画等长的 3 秒口播，先不加插帧。

**适合你的成片：** 口播同一段结构下改一句商品介绍；真人说明片的多版本台词。将脸部变化与原片其余区域分别检查，必要时只回贴合适的面部区域。

**验收重点：** 听音辨口型、闭口时机、齿部、胡须、头部转动、面部边缘，以及是否保持原身份。侧脸、遮嘴、多人说话分别建立后续困难集。

### C06 · Wan-Animate 官方替换演示：现有人物替换的基准

**证据：研究作者演示。** 项目页有角色动画、人物替换、环境融合、光色复制等分区，可用于理解输入参考图、驱动视频与输出的关系；这些是筛选后的展示，不是业务通过率统计。[Wan-Animate 项目页](https://humanaigc.github.io/wan-animate/)

**本地迁移：** 保留你已经跑通过的单人替换作为基准，与第一轮公开 WanAnimate 图做同素材对照。固定参考图、动作视频与尺寸，不同时更换多个模型和预处理方案。

**适合你的成片：** 同一个简单动作的不同出镜角色、服装外观或人物版本。先分开验收脸、服装轮廓、手与背景保持，避免把“整体看起来像”当作全部通过。

**本轮新定位：** 这条路线继续保留，但不再代表整个混合视频工作台。它是众多“真实表演→生成角色”的一种。

### C07 · UniLumos：同一真实前景如何融入不同光照

**证据：作者标注的真实 UGC 演示＋公开推理路线。** 项目展示前景／背景组合网格，并提供文字、前景视频、背景视频等不同输入组合的重打光方式；官方页面也链接了 ComfyUI 集成。[UniLumos 项目说明](https://github.com/alibaba-damo-academy/Lumos-Custom/blob/main/UniLumos/README.md)

**本轮补齐：** 已保存 Kijai 的 1.3B UI 示例，确实包含两路视频和 `WanVideoUniLumosEmbeds`。第一轮“尚未保存补光图”的缺口已经补上；仍未验证运行和观感。

**本地迁移：** 同一人物前景＋暖光室内、阴天户外两种背景，对比：①直接合成；②普通色温／曝光调整；③UniLumos。先输出低分辨率短片，只在③显著改善且不破坏身份时加入生产链。

**3090 起点建议：** 从 512×288、33 帧短片做加载与条件检查，再尝试 49 帧及更高分辨率。这是调试起点，不是画质推荐档。示例的蒸馏 LoRA 与采样设置应成组保留，不能只把任意模型步数降到相同数字。

**边界：** 生成式重打光可能重新生成细节。对商标、衣服图案和脸部，应有独立通过条件；硬光方向严重冲突时，重新选背景可能比继续生成更有效。

### C08 · Mark DK Berry 的局部合成实验：低显存按区域做

**证据：创作者公开制作说明。** 作者的 2025 研究页记录了 RTX 3060 12GB 环境下，将人物局部裁出、用 WanAnimate 处理、再在剪辑软件回贴的做法。它证明有这类制作实践；原片未被本轮证实为真实 UGC，不把它算作实拍效果验证。[作者研究页，Compositing 分区](https://markdkberry.com/workflows/research/)

**本地迁移：** 把裁切范围、缩放比例、起止帧、遮罩及回贴变换变成任务资料。先做固定 ROI；人物移动超出范围时再增加跟踪。裁片要保留上下文，不能把目标裁得只剩轮廓。

**适合你的成片：** 多人画面只改一个人；一段已有结果只修一处脸部或背景物体；避免为了小缺陷反复处理整幅画面。

**必须接受的成本：** 合成仍有边缘、颗粒、运动模糊与遮挡处理。裁小不等于自动变快、变好，也不能用 3060 作者耗时按显存比例推算 3090 耗时。

### C09 · VACE Clip Joiner：真实段与 AI 段之间的接缝

**证据：工具作者演示＋完整图。** 仓库的 Bowie、Jungle、Neon 示例来自 Wan 2.2 首尾帧生成片段。作者宣称可处理其他视频来源，但这批示例不能证明“任意手机视频接 AI 视频”已成立。已下载 lightweight 与 full 两个图。[作者仓库及 Examples](https://github.com/stuttlepress/ComfyUI-Wan-VACE-Video-Joiner)

**本地迁移：** 从构图接近、主体数量相同的两段片开始，用接缝前后上下文生成过渡；只改接缝区域，保留远离接缝的原片。比较硬切、普通叠化、VACE 三种结果，硬切也可能是最佳选择。

**适合你的成片：** 真人走向门口，接 AI 生成的同方向移动镜头；实拍产品展示接环境变化镜头。不能期望用转场掩盖完全不同的主体几何或动作逻辑。

**边界：** 作者记录了色亮变化、帧数不匹配导致重影、子图版本兼容等问题。先用 lightweight；确认两段短片收益后再研究 full 的目录批处理。两个图默认含 14B 高低噪模型，文件名“轻量”主要指工作流结构，不代表小模型或低显存保证。[轻量版说明](https://github.com/stuttlepress/ComfyUI-Wan-VACE-Video-Joiner/blob/main/README-lightweight.md)

### C10 · SCAIL-2 人物与物体交互：应当用于困难测试

**证据：作者研究演示。** 项目页按遮挡、人物物体交互、跨身份及复杂运动等展示人物替换，还介绍直接视频条件路线。公开示例能提示测试方向，不能证明任何商品、手势和身份都能保持。[SCAIL-2 项目页](https://teal024.github.io/SCAIL-2/)

**本地迁移：** 第一轮保存的 SCAIL-2 INT8 图只作为候选，对照现有 WanAnimate。四级测试：空手动作 → 拿不透明杯 → 手遮挡脸 → 人与物体同时快速运动。每次只提升一级难度。

**适合你的成片：** 更复杂的角色替换、动作迁移或互动演绎。若产品本体必须精确，仍优先 C03 的商品保护路线；SCAIL-2 的交互能力不等于包装文字保真。

**3090 定位：** 第二批实验；INT8 权重不代表全部预处理与生成可以同时驻留 24GB。先离线预处理并释放显存，再做短片推理。

### C11 · ProPainter 物体移除：值得保留的传统视频修补对照

**证据：研究项目＋输入／遮罩样本。** 作者提供视频修补演示，仓库有 `bmx-trees`、`tennis` 及对应 mask 目录，可用于成对实验。模型和代码的非商业使用条件使其更适合作为本报告的技术对照。[项目页](https://shangchenzhou.com/projects/ProPainter/) · [原始样本目录](https://github.com/sczhou/ProPainter/tree/main/inputs/object_removal) · [仓库与许可说明](https://github.com/sczhou/ProPainter)

**本地迁移：** 对“背景曾在邻近帧出现”的移除任务，对比时序修补与 VACE。使用同一视频、同一遮罩和相同输出尺寸，观察背景能否连续恢复。

**适合你的实验：** 去除小范围背景干扰物。若目标后面的背景从未出现，就要允许生成推断，不能承诺恢复真实隐藏内容。

**定位：** 帮助区分“借用已有画面补全”和“生成新内容”两类问题；不作为当前商业批量默认模板。

## 4. 分类进一步细化：按保留资产和改变资产定义产品

第一轮 7 大类、26 小类继续作为能力目录。本轮新增下面这层“产品配方”，让分类能够直接指导选素材与绑定输入。每条成片可以组合两三种配方。

### 三个更接近日常 UGC 的首发内容方案

**方案 A：同一真人的三种日常场景。** 拍摄一段固定机位、自然语气的短口播，准备书房／厨房／露台背景。人物和声音保留，分别检查发丝边缘、桌沿遮挡和光向。这是 T01＋必要时 T04，适合先验证“看起来还像真实拍摄”。

**方案 B：真商品的一天。** 实拍拿起、展示、放下商品三个短动作；每个动作单独选一个环境。商品小字与手部保留，环境变化以切镜实现，暂不要求跨场景连续变形。这是 T02＋T10，适合形成可批量换背景的母片。

**方案 C：口播＋证据镜头。** 实拍开头与结尾，中间插入环境、抽象原理或场景补充镜头。商品实物细节仍用实拍，AI 镜头承担无法方便拍摄的说明画面。这是 T03／T10 的组合；字幕、配乐和转场用固定剪辑模板处理。

这些是为本项目设计的内容提案，并非上述品牌已发布的同款方案。建议成片保留自然停顿、适当镜头噪点与实际拍摄节奏；不把过度磨皮、强锐化和持续夸张运镜作为默认风格。

## 5. 3090 的实验顺序与止损条件

**先做 4 条通路检查，再做 36 个生成结果的对照小样。** P01–P04 每组使用 3 个素材，每个素材最多 3 次生成候选，共 36 个；普通合成、调色或原片作为额外基线，不计入这 36 次。模型更换时另开实验，不挤进同一组混计。P05 接缝单列探索，首批暂不扩量。

| 实验 | 比较对象 | 关键不变量 | 主要失败信号 | 暂停条件 |
| --- | --- | --- | --- | --- |
| P01 真人换背景 | 普通合成／调色／UniLumos | 身份、衣服、原动作 | 发丝闪、脚底漂、脸变、光向冲突 | 普通合成已更自然，或补光频繁改脸 |
| P02 真商品换场景 | 原商品保护合成／VACE 背景编辑 | 包装字、边缘、手部接触 | 字漂、反射不符、穿模、商品轮廓变化 | 简单静物保护都不稳定，停止上手持难片 |
| P03 真人口型 | 原片／录音驱动 LatentSync | 身份、时长、单一说话人 | 闭口错误、齿部闪、边缘跳变 | 连续简单正面片均失败，先查对齐与版本 |
| P04 局部修补 | 整段重跑／ROI 修补回贴 | 非编辑区域与原时间线 | 边缘呼吸、回贴漂移、其他区域受损 | 返修耗时接近重做且质量无改善 |
| P05 接缝 | 硬切／叠化／VACE Joiner | 主体、方向、前后文 | 突然变形、亮度跳变、重复帧 | 任一普通剪辑更合适，就采用普通剪辑 |

详细素材规格、输入槽位和执行步骤见[实验任务单](实验任务单.md)。上述阈值与预算是建议，不是已完成的实验数量或结果。

### 只测能支持决策的指标

- **首试通过率**：固定第一 seed 的合格输出数／素材数。避免只挑最好结果。
- **三次内可用率**：最多三次候选内取得合格版本的素材数／素材数。与首试通过率分开记。
- **每条可用镜头总耗时**：预处理、生成、失败重试、人工检查、合成全部计入；记录冷启动与模型已加载两种情形。
- **保真失败项**：人脸、包装字、手部接触、背景边缘、动作物理、声音对齐逐项通过／失败。关键项失败即退回，不用平均分掩盖。
- **运行资源**：峰值显存、峰值系统内存、分辨率、帧数、模型精度、卸载策略和插件版本。

3 个素材只是探索，不足以宣布批量成熟。探索通过后，固定配置再用至少 10 条新素材验证；保留所有失败，不能把同一条素材反复改出来的结果当独立样本。

### 显存与帧率安排

按“分割 → 保存 mask → 卸载 → 生成 → 卸载 → 解码／合成”串行执行，尽量复用预处理结果。首轮使用短镜头和小画幅，找到失败原因后再升分辨率。14B 模型需要按对应加载器核对量化与卸载，不因为文件有 FP8 就假设 3090 的原生 FP8 加速可用。

Wan 类调试可从 33／49 帧、16fps 的短片起步；LatentSync 另走 25fps 对齐，不把全库统一强制成 16fps。Clip Joiner 还要满足它自己的上下文与替换帧数要求。声音独立保存，最后按明确的时间线合回，避免简单改帧率造成语速变化。

## 6. 工作台下一步应该支持什么

第一轮静态检查发现，当前投递主要围绕单张图片和单个视频，编辑器也尚不是多轨合成管线。以下是研究导出的改造建议，本轮没有改生产代码。

| 能力 | 对应案例 | 最小改造范围 |
| --- | --- | --- |
| 命名输入槽位 | UniLumos、LatentSync、Joiner | `source_video`、`background_video`、`target_audio`、`reference_image`、`edit_mask`、`protect_mask`、`clip_a`、`clip_b` 独立投递 |
| 多张图片分别绑定 | 首尾帧、角色与商品参考 | 禁止多个 LoadImage 默认共用一张图；模板声明每个槽位绑定哪些节点 |
| 镜头级与区域级任务 | Visa 修补、局部合成 | 起止时间、ROI、遮罩版本、回贴变换、母版路径、父任务 ID |
| 中间产物缓存 | 所有路线 | 帧序列、mask、姿态与音频可复用；调整提示词不重复分割 |
| 可比较的版本记录 | 所有路线 | seed、图版本、模型版本、参数、候选视频、通过项和失败项一起保存 |
| 可重复的成片模板 | 口播＋B-roll | 镜头顺序、保留原音、旁白起点、字幕与输出规格；先调用确定性剪辑工具 |

**最小实施顺序：命名输入与音频投递 → 短片保存与对照 → 遮罩／ROI 回贴 → 成片模板 → 多段生成式衔接。** 双视频不能只作为字符串写入参数：必须分别上传或复制到 ComfyUI 可访问的位置，再绑定加载节点。

## 7. 下一轮怎样继续迭代

每轮只追一个可判定问题：例如“保留真商品能否比重绘商品显著减少标签错误”，而不是继续积累模型名。

1. **案例轮：** 找到原片／结果、作者工艺、硬件或文件；标记缺失项。本轮已完成这一层。
2. **通路轮：** 指定图版本，用自己的最简单素材跑一个小样；修复输入与依赖问题，记录能够运行的版本。
3. **对照轮：** 固定素材和候选预算，对比两条路线；记录所有失败和人工时间。
4. **产品轮：** 只把通过的路线做成模板，定义可接受素材范围和拒绝条件。
5. **扩展轮：** 每次只新增一种困难条件，如手持、转头、快速移动或多人遮挡；结果回写分类和优先级。

下一轮最值得回答的是 **P01 的普通合成是否已经足够、P02 的商品保护范围如何定义、P03 的本地口型链能否稳定运行**。这三项未跑通前，暂不把重运镜、复杂交互和长视频自动衔接列为批量生产目标。
